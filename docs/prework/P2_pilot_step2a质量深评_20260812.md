## 2. 逐条评审发现

**先澄清一个关键事实**：传输与结构层全部合规——请求正确送达（含全部锚点/表格/义务上下文）、响应是合法 V25 payload、锚点 ID 全部真实存在（无幻觉锚点）。**问题纯在内容判断层。**

**合格面（约 25-30%）**：表格类 composition 聚合普遍合格甚至优秀。例：gonglu_01「特殊路基分类表」（三分类 17 种路基全对、锚点干净，即基准 `special-types-table` 的语义等价物，仅标题措辞差）；gonglu_62「材料费计算表」「机械租赁费计算表」「预算直接成本类型及依据表」均内容准确、锚点成组正确。

**缺陷面（系统性，约 70%）**：
1. **考情统计当知识点**（10 条）：把「历年题量表」「（2019、2023、2024 多）」「（2022 案）」这类考试元数据单拎成提案，且 fact_type 误用 threshold（把题数当工程阈值）。
2. **行级碎片化**（单锚 threshold 45 条的主体）：跨行公式被拆成「材料单价公式前段」「后段」各立提案；例题被拆成「示例条件前段」「后段」「示例答案」三条——把证据行当知识点，完全没做教学语义聚合。gonglu_55 尤甚（53 提案 vs 5 目标）。
3. **水印噪声不筛**：源证据里的水印散字（「信」「微」「系」「联」「题」——V2 证据面的已知噪声）被原样收进 assertion（gonglu_01「路基排水包括8、地下水排水设置与施工 3、信、…」）。
4. **教学目标丢失**：28 个人工基准目标绝大多数无合格对应（learning_golden 五章 0 匹配；gonglu_01 的 diagram 目标完全没有 diagram 类提案）。

## 6. 流式（SSE）传输改造实测（20260812 深夜，r6 轮）

驱动新增 `--stream`：`StreamingStep2Transport` 覆盖 `_raw_create` 单点（探针/业务共用），SSE 聚合 delta 后返回与非流式同构的 TransportCompletion，请求语义零变化。实测（`--reinforce --stream` 五章新身份）：

- **实质改善**：最重的 gonglu_24（250KB payload）以 **194 秒完整跑完**——非流式下必死于 125s 窗口；五章首发 3/5（vs 非流式补强轮 2/5）。
- **未根治**：gonglu_55/62 仍在 ~124-130s 被掐（502/524）——网关掐的实为**首字节延迟**：模型思考期无 SSE 字节流动，思考 >125s 照掐。流式把掐断条件从「总时长」改善为「首字节」。
- 重发兜底仍必要：55 章重发 96s 过；62 章当晚三连挂（该章思考期长 + 当时段中继波动），其质量数据以非流式补强轮的成功产物为准（84s，`step2_live_56sol_rf_r2`）。
- **生产配方定稿：2chat + gpt-5.6-sol + 补强指令 + SSE 流式 + 失败章自动重发（≥3 次）**。65 章全量跑按首发 60% / 重发累计 >95% 口径预留重发预算与时长。

**step3 新配方复测（同晚，两轮）**：`--stream` 下连接分别存活 182s/244s（流式确实突破了 125s 窗口），但两轮均以上游 APIError 告终、零内容返回——**2chat 的 5.6-sol 无法完成 step3 三卡 strict 回显**（~4-6K tokens 超长受约束生成，上游持续失败；叠加此前 chatgpt2api 不约束解码、2chat gpt-5.5 网关掐断，三条路径全部证伪）。step3 的可行出路：① 将来接入官方/高保真端点；② 工程路径——新契约版本改单卡回显（输出量降为 1/3，v1 契约钉死三卡故需 v2 版本号），建议在 65 章全量跑立项时一并裁决。注：step3 在黄金五章上的引擎链路验证目的已由 16 卡 reviewed 发布 fixture + step4 16/16 实拍覆盖，此项不阻塞全量跑立项，仅阻塞「新卡的全自动 step3」。
