## 3. 关键发现（候选序源头，防后续踩坑）

语料 fixture 的候选序 = **r89 run `admission-candidates.json`（bundle_sha256 封印清单本体）的顺序**，
即权威队列序；而 r810 run 自身的 `production-decision-manifest` / `disposition-projection` /
`decision-audit` 是按 `candidate_id` 排序的**另一序**。用后者做摄取序会得到合法但不同封印的
fixture（实测 58f1c9db… ≠ 语料 3f5f8acc…）。实现方 API 以「`queue_items` 传入序 = 摄取序」承载
该语义（`1d85fea` 已注明 QUEUE order），验证侧从 r89 admission bundle 取序对拍通过。
