# P3 协同机制经验教训（20260813 凌晨班总结）

- 场景：协同工作组「一建2重构」，总指挥 + 8 成员（pchat hub 调度，共享同一台机器、同一份仓库检出），一夜完成 P3 方案 T1-T5 全轨终局。
- 写作视角：总指挥（`yijian2-ready`，01:20 接任）。素材=本班全部裁决、事件与任务往来；量化结果见 `P3_总指挥交接台账_20260813.md`。
- 结论先行：**机制本身能跑出高产出（约 3 小时、20+ 任务卡、9 个入库提交、pytest 477→644 零回退、$2.6 花费拿下终态），但夜里暴露的 8 类失效模式全部指向同一根因——hub 的「状态视图」与「实际执行」会脱节；靠 11 条纪律准则兜住了零产物损失。**

## 2. 为什么零产物损失（防线复盘）

1. **已提交状态优先（committed-state-first）**：换人接管都以 origin/main 为基座（T4b 接管时全部实现恰已入库，接管成本最低点）；未提交他人 WIP 一律「快照后 checkout 丢弃、报告记档」，绝不提交他人半成品。
2. **隔离不删（quarantine-not-delete）**：僵尸叠层块、可疑 untracked 文件全部快照进 `.test-tmp/` 留证再清理；git 历史即证据链。
3. **哨兵条款（sentinel clause）**：接管任务书里写明「发现非你创建的 run 目录出现→立即停手报总指挥」——正是这条让续跑者在双跑 live 花费发生前 stop（F2 反转的关键）。
4. **双向停止令**：对「疑死」方下 stand-down（含"若我误判你在跑 live，立即回我叫停续跑者"的反向出口），对接管方留 abort 道——误判可无损回退。
5. **预算护栏实弹两次拒付**：run b 预检熔断、收口期并发双 resume 被 call-cap 拒付——花钱面的最后一道闸真实有效。
6. **写锁 + 写面分区 + 小步快提交**：locks 用于 README/git-push/docs 热点；任务书 workspace.paths 声明写面；小步提交让已落库内容不可被叠坏。
7. **交接台账入仓**：总指挥班次台账（track 表+事件簿+接任者手册）直接 commit 进 docs/prework——掉线保险不再依赖聊天导出（本班根因风险的对症药）。

## 3. 有效准则沉淀（P1-P11，可直接复用的打法）

1. **P1 以实际写手+可验证产物为准**，卡面账本随后校正——所有权属纠纷（叠写、漂移、双派）一律先看「谁的字节在仓里、能否验证」，不看卡面挂名。
2. **P2 双独立验证默认制**：回归守卫双腿（方法互独：git-diff-空 vs 哈希三方全等）、转换器双签（实现 vs 零共享代码路径重放）、评审双轮（主评+独立复判）——把「多会话乱局」反向转化为「独立性红利」。
3. **P3 continue-not-redo 接管纪律**：接管卡必须写明「基座提交号 + 只做剩余部分 + 归属分记」，严禁重写已入库实现。
4. **P4 停止令双向化 + 修正令覆盖机制**（见 §2.4）。
5. **P5 快照隔离不删**（见 §2.2）。
6. **P6 小步快提交**：长任务把无争议部分先落库，脏树窗口越短，叠写伤害越小。
7. **P7 写面独占声明 + 边界外顺手活先问再动**：预铺方代落 .gitignore 两行虽良性，仍按「越界」记纪律课——两头知会防重复才没出事。
8. **P8 任务书结构化且携带环境坑位**：objective/acceptance/boundaries/workspace 五字段之外，把 ACL 病规避口径、哨兵条款、费用授权直接写进卡——省掉一轮往返。
9. **P9 交接台账入仓制**（见 §2.7）——建议每个总指挥班次开班即建、终盘定稿。
10. **P10 评审人预定制**：检查点物料未出前先锁定评审人并让其预读契约（§7.1/§7.2），物料一落地评审即刻开跑——本班检查点②从出料到关账约 1 小时。
11. **P11 诚实反压**：对「让 N 人并行」的系统提醒，只在真有可并行工作时扇出；串行关键路径期宁可留人待命也不造假活——本班三次顶住反压，事后看全部正确（硬拆必撞 T4b/预铺/转换器写面）。

## 4. 对 hub/平台的改进建议（H1-H7）

| # | 建议 | 治什么 |
|---|---|---|
| H1 | 交接协议增「旧窗口处置」步骤：换绑成功后强制旧会话进入只读/终止态，至少横幅警告用户手动关闭 | F1（本班唯一真险源） |

## 5. 结语

今晚的净结论不是「协同机制脆弱」，而是「**状态视图与实际执行的脱节不可避免，但完全可治理**」：治理手段（P1-P11）全部是流程纪律而非新基建，成本≈零；hub 侧七条改进（H1-H7）中 H1/H2/H3 三条能消掉本班约 80% 的裁决工作量。机制+纪律的组合拳最终把 8 类失效模式全部压制在「零产物损失、零红线违反、$2.6 总花费」之内，并顺手把两处驱动盲区变成了入库修复——**乱局被验证性纪律转化成了质量红利**。
