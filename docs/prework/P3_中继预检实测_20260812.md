## 1. 双中继能力矩阵（20260812 实测）

| 能力项 | chatgpt2api-new (127.0.0.1:3100) | 2chat (https://2chat.cc/v1) |
|---|---|---|
| P1 请求体上限 | **[40,70)KB**（12✓ 40✓ 70✗502 120✗502，连续两败止损） | **≥260KB 未触顶**（12/40/70/120/180/260 全过，260KB 级 28.8s） |
| P2a strict 强制解码 | **否**——诱导空数组成功逃逸，schema 仅被当提示 | **是**——诱导空数组失败，minItems=3+const 被强制解码（2.7s） |
| P2b 单卡级回显（~1.5K token 输出） | echo_exact，15.5s（模型自愿配合，但无 strict 保障） | **echo_exact，26.9s**（远在网关窗口内） |
| P3 首字节窗口（--deep） | 未跑（本地服务无网关层） | 非流式 **~125.2s 被掐**（HTTP 524/CF html）；流式首字节 1.1s、首内容 3.5s、**存活至 175.4s**（确证越过掐点后主动中止省费）→ **掐断条件=首字节/空闲，流式可续** |
| P4 /models 广告 | gpt-image-2 **在售**（12 模型；gpt-5.6-sol 不在售） | gpt-image-2 **不在售**（图像通道按双通道设计走 3100） |
| P4 实际出图（--with-image） | HTTP 200 出图成功（b64_json 变体、1.1MB、45.7s），**但严格信封门禁 FAIL**（见 §2 漂移发现） | 未跑（不在图像通道） |

## 2. 与昨日实测（P2_pilot_黄金五章全链实测）的一致性对照

| 昨日结论 | 今日复测 | 判定 |
|---|---|---|
| chatgpt2api-new 体积上限 40-70KB | 上限区间 [40,70)KB | **一致** |
| chatgpt2api-new strict 不强制（step3 空数组逃逸） | P2a 空数组逃逸复现 | **一致** |
| chatgpt2api-new 图像可用（16/16 过信封门禁） | 出图仍成功，**信封漂移**：`data[0]` 键集从 `{b64_json, revised_prompt}` 变为 `{b64_json, height, width, revised_prompt}` → r118 严格适配器（unknown_fields_allowed=false）判 `data_item_exact` FAIL | **发生真实变化**（见下） |
| 2chat 体积无限（12→260KB 全过） | 六级全过 | **一致** |
| 2chat 网关 ~125s 掐断 | 非流式 125.18s、HTTP 524 复现 | **一致** |
| 2chat strict 遵从性未知（step3 死在网关之前） | **补齐：strict 强制解码** | 新信号 |
| 2chat 图像未测 | 补齐：/models 不广告图像模型 | 新信号 |

**漂移发现（重要）**：3100 图像信封今日多出 `width`/`height` 两键。昨日 16/16 全绿的 step4 生产驱动若今日重跑，将在同一门禁上全数 FAIL。这正是预检工具要抓的故障类别（图像信封变体），处置建议：
1. 任何 step4 live 跑批前先跑 `relay_preflight --with-image` 确认信封形态；
2. 若漂移持续存在，需评审是否把 `width/height` 纳入 `ImageEnvelopeProfile` 画像 allow-list——这是冻结面（providers 画像钉扎）决策，须按冻结纪律走新画像版本，不在 T1 范围内擅动。

## 3. 需求画像结论（工具自动输出）
