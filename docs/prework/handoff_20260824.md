## 一、这个仓库在做什么

考试知识图解卡片生成引擎的 **V2 内核**，从旧仓 yijian2 抽包而来。主链路：

```
materials（原始材料） → evidence（证据抽取/融合/视觉核验） → knowledge（事实、卡片、契约、续传）
    → compilers（step3/step4 编译成请求与制品） → gates（判定/闸门/发布就绪）
```

全链条贯穿「闸门 + 人工审阅」：`gates/` 里的判定逻辑是唯一裁决权威，`webui/` 只做展示。

一级子包锁定 **10 个**：`materials / evidence / knowledge / compilers / gates / pipeline / providers / common / utils / webui`。

文档与代码注释一律中文，**给用户的答复也必须是中文**。关键活文档：

- `docs/engineering_skeleton.md`（170 行）：布局终裁、依赖方向、测试隔离条款 T1–T8、产出路径纪律
- `docs/extraction_manifest.md`（451 行）：旧仓 → 新仓抽包清点清单 v3，由 `migration/gen_extraction_manifest.py` 生成（**改一处必须两处同改**）
- `docs/prework/*.md`：拆分蓝图与施工方案（cm21 新增 `fact_engine_split_blueprint.md`）

## 二、环境与工具坑（**先读完再动手，这一节全是踩过的坑**）

1. **实际是 Windows + PowerShell**，尽管注入的系统上下文写着 linux、CWD 为 `/`。`uname -a` 会失败，`pwd` 返回空。每条命令都要先 `cd 'c:\Users\liushaocheng\Desktop\getinfo\exam-card-engine'`。解释器用 `.venv\Scripts\python.exe`。`uv` 可用（`uv lock` / `uv lock --check` / `uv sync` / `uv add --dev`），`uv.lock` 是权威。

2. **Shell 工具不稳定（长期存在）**：常返回 `<shell-incomplete>`「Missing terminal shell stream event」，前台等待窗口在 0ms/12s/…/60s 到期，而命令**可能仍在后台跑完**。应对：
   - 命令短、单一目的；输出 tee 到 `.test-tmp\<name>.txt` 再 Read 文件；
   - 状态变更一律用 Read/Glob/Grep 复核（cm21 的拆分落盘就是这样确认的——生成脚本的 tee 日志根本没落地，靠 Glob 数出 13 个文件才确认成功）；
   - 重跑前先检查副作用是否已发生。

3. **pytest 必须显式 `--basetemp`**：系统 tmp 根 `$env:TEMP\pytest-of-liushaocheng` 是 access-denied，不给 basetemp 会得到约 110 个收集/setup ERROR（证据 `.test-tmp\nobasetemp.txt`）。CI 与文档示例里也都带着这个参数。

3b. **VM 内的 Linux 环境还要给 pytest 加 `--ignore=.pytest_cache`**：仓根那个目录在 VM 里连 `stat` 都被拒（Permission denied），pytest 遍历 rootdir 时会直接 `ERROR . - PermissionError` 整跑失败；`-p no:cacheprovider` 救不了，因为失败发生在目录遍历阶段而不是缓存写入阶段。该目录本来就在 `.gitignore` 里，加这个参数不影响任何判定。

4. **Shell 的成功/失败只等于管道最后一个元素的退出码**。接了 `Tee-Object` / `Select-Object` 之后它毫无意义——历史上因此误判过三次（nw13 误读成「干净」、cm18 误判成失败、cm20 严格档 mypy 惊魂）。判定一律看日志末行的 `Found N errors in M files` / `Success: …`；要退出码就单独 `; "ruff_exit=$LASTEXITCODE"`。ruff 与 mypy **分开两条命令**跑。

5. **中文日志的编码**：生成时设 `$env:PYTHONIOENCODING='utf-8'`，读回时用 `Select-String -Encoding UTF8`。Read 工具读某些 tee 日志会显示成 GBK 乱码。`git diff` 经 `Out-File -Encoding UTF8` 会产生乱码（`cm19_diff_*.txt` 就是废品）——**要看改动就直接读源文件**。

## 三、仓库硬约束（改动前必须知道）

1. **字节权威仓**：`.gitattributes` 把所有路径标成 `-text`，禁止任何 EOL 归一化。金样/夹具/canonical 哈希锚定的是**工作区字节**。每次改完跟踪文件都要复核 HEAD 与工作树的 CRLF/BOM 平价；未跟踪文件直接按字节扫。

2. **字节权威不延伸到 Python 模块路径**：`__module__` / `__qualname__` / `__file__` 从不进入任何被哈希的载荷。所以只要公开导入面不变，拆分/搬迁**对金样哈希是安全的**（cm21 已实证）。真正的阻挡是测试层的布局封印和反射 import，不是字节权威。

## 六、mypy 关码棘轮的现状（这是本系列的主线之一，cm29 已见底，cm30 又降一条）

**`pyproject.toml` 里不再有任何 `disable_error_code`。** 首测 263 条 / 35 个模块的逐模块
豁免清单，经第 1~8 批「按正解真修」退到 6 个模块 / 18 条（cm23 退 `knowledge.llm`），cm29 把最后这 18 条收口：

- **2 条是真错**（`contracts.admission_legacy_hash` 的 `call-arg`）：`hash_model_r8x` / 
  `hash_model_r102` 补默认值那行写的是 `field.default_factory()`——零参调用。pydantic v2 把
  `default_factory` 标注成 `Callable[[], Any] | Callable[[dict[str, Any]], Any] | None`，
  也就是允许**单参**工厂，旧写法遇上单参工厂会在运行时 `TypeError`。**旧 pyproject 注释把这
  2 条误诊成 `model_construct` 插件假阳性**，是本轮预研纠正的判断。已按正解改用
  `FieldInfo.get_default(call_default_factory=True, validated_data=...)`；等值实测：全仓 500 个
  模型 / 1428 个默认值字段（其中 2 个 `default_factory`）两种写法逐个相等且同型，canonical
  载荷与所有旧口径哈希不变。封在 `tests/test_knowledge_contracts_admission_legacy_hash.py`
  （9 个用例，含两条血脉的字面量摘要与「r8x 计入 / r10x 排除 `schema_version`」的差异）。
- **16 条是工具/上游限制**，改成**行尾逐点 `# type: ignore[码]`**，每处旁边写明为什么：
  `step2a_builders:438` 一行 10 条（pydantic 插件给 `model_construct` 合成「必须列全字段」的
  签名，真实契约是部分赋值 + 跳过校验）、`knowledge/schema` 与 `knowledge/quality` 各 2 条

## 八、拆分方法论（cm21 的可复制流程）

1. **预研扫描**（只读 AST，不改仓）：
   - `.test-tmp\splitscan.py <文件…> [--graph]` → 顶层定义清单（kind/name/行区间/字节量）+ 顶层符号互引图，**区分运行位与注解位**；

5. **门面**：保留原模块 docstring，`__all__` **精确列出拆前的全部顶层符号**（私有助手也要列——随迁测试确实 import 私有函数；门面的职责是 100% 兜住原有名字面，不是趁机重新定义什么算公开）。
