### 1.1 本机环境损伤（两处，同一病因）

`%TEMP%\pytest-of-liushaocheng` 与仓内 `.pytest_cache/` 均处于 **ACL 拒绝访问** 状态（推测由某次管理员权限运行创建），非管理员无法删除/改名/重置权限：

- 前者导致 pytest 的 `tmp_path` fixture 初始化失败 → 裸跑 84 个 ERROR；
- 后者仅导致缓存写入告警（不影响判定）。

**修复（管理员 PowerShell 一行）**：

```powershell
takeown /f $env:TEMP\pytest-of-liushaocheng /r /d y; icacls $env:TEMP\pytest-of-liushaocheng /reset /t /c; rd -r -fo $env:TEMP\pytest-of-liushaocheng; takeown /f C:\Users\liushaocheng\Desktop\getinfo\exam-card-engine\.pytest_cache /r /d y; icacls C:\Users\liushaocheng\Desktop\getinfo\exam-card-engine\.pytest_cache /reset /t /c; rd -r -fo C:\Users\liushaocheng\Desktop\getinfo\exam-card-engine\.pytest_cache
```

修复前的替代口径：`uv run pytest --basetemp .test-tmp/pytest-base`（T3 规范收口区内，已验证全绿）。

## 3. 优化路线图（建议顺序）

| 轨 | 内容 | 工作量 | 解锁价值 |
|---|---|---|---|
| **T1 中继能力预检工具** | 把体积探测扩成四合一自检：体积阶梯 + strict json_schema 强制性检验（含空数组逃逸探针）+ SSE 首字节/总时长窗口 + 图像端点探针；一键出报告 | 小（~1h） | 未来换中继/换模型从数小时诊断压缩到分钟级；全量跑前的标准前置检查 |
| **T2 生产配方产品化** | `examcard.knowledge.llm` 增可选能力：SSE 流式聚合（等价 TransportCompletion）、system 补强注入点、失败章重发辅助；pilot 驱动改薄为调用方；**不触碰法定哈希与冻结契约**；补 T2 级测试 | 中（~2-4h） | 任何未来考试开箱即得达产配方；migration 私有补丁归零 |
| **T3 step3 v2 单卡契约** | 新版本号（v2）单卡回显契约 + 编译器 + 响应门禁 + 测试；用黄金五章 16 卡实测验证可行性（~$0.3） | 中大（~4-8h） | 解除新卡全自动 step3 断点——未来考试全链自动化的最后一环 |
| **T4 通用全链 live 驱动** | `exams/<exam_id>/` 一键 step1→2a→2b→3→4：Material Profile 驱动、预算护栏、断点续跑、审计落盘（依赖 T2/T3） | 大（1-2 天） | 新考试接入从"手册分步"变"一条命令" |
| **T5 文档沉淀** | runbook §8 补生产配方与中继能力矩阵；.env 双通道约定成文；本机 pytest 环境修复指引入 README/骨架文档 | 小（~0.5h） | 交接与复现成本降低 |

建议执行序：**T1 → T2 → T5 →（拍板后）T3 → T4**。T1/T2/T5 当天可完成且零风险（不动冻结面）；T3 引入新契约版本号需按冻结纪律走新增（不改 v1）；T4 依赖前三者。
