## 1. 包现状：两个文件、纯函数、无路由

| 文件 | 内容 |
|---|---|
| `src/examcard/webui/__init__.py` | 仅 docstring（宣称"flask 审阅工作台"是**布局占位语**，包内实际零 flask 代码） |
| `src/examcard/webui/review_workbench.py` | 全部实现：`compact_queue_entry()`（队列条目投影）+ `render_review_workbench()`（渲染静态单文件 HTML，规范源 r83） |

关键事实（决定选型的地基）：

- **没有 HTTP 层**：无 flask 路由、无视图、无 `[project.scripts]` 入口、无启动脚本。`pyproject.toml` 里的 `flask>=3.0.0` 目前是**未被 src 任何模块 import 的闲置依赖**（测试 `test_workbench_module_never_imports_flask_or_gates_upward` 反而用 AST 断言 webui 不得 import flask）。
- **产物是自包含单文件 HTML**：队列 JSON 内联注入（`<script id="queue-data" type="application/json">`，`</` 转义防截断）；样式/脚本全内联；**源页图不内嵌**，按根绝对路径 `/output_images/...`（非 ASCII 段百分号编码）经 HTTP 拉取——所以"启动"= 渲染 + 在正确的根目录起任意静态文件服务。
- **依赖方向合法**：webui → gates.review（`PENDING_DECISION_HASH`、`PRESENTATIONS`）单向向下，判定逻辑零上浮。

## 2. 装载什么数据（问题"fact run？evidence？卡片？"的准确答案）

工作台装载的是 **step2 准入内核的"人工评审队列"投影**，不是 fact run 原始产物、也不是 step3/step4 卡片：

- `compact_queue_entry(item, candidate)` 消费鸭子类型的队列项（形如 `gates/review/queue.py` 的 `ReviewQueueItemBase`/`AdmissionQueueItem`）+ 候选对象，投影出：`candidate_id / queue_item_id / subject_id(+label) / record_id / fact_id / evidence_id / presentation / source_manifest_sha256 / anchor_ids / pages[] / disposition`。
- 每个 `pages[]` 元素来自 `SourcePageBinding`：`page_ref_id / page / source_file / image_uri（根绝对+URL编码）/ image_sha256 / image_width / image_height`——即**每条待审项直接绑定 Fact/Evidence/anchor 与源页图证据**。
- `queue_sha256` 由 `gates/review/queue.py::queue_sha256()`（r8x 法定哈希谱系）计算，作为决策/清单/审计的链绑定标识贯穿始终。

## 3. 界面能力清单（客户端，实测核对）

| 能力 | 细节 |
|---|---|
| 侧栏过滤 | 科目下拉、呈现类型下拉（五呈现 `diagram/table/ordered_list/constraint/formula`）、搜索框（queue_item_id / record / Fact / 源文件名），计数 `x / total` |
| 条目详情 | candidate / queue item / record / Fact / Evidence / source manifest / anchor 七元身份网格 |
| 源页图检视 | 逐页展示 `page N · image_sha256 · 宽×高` 标题 + `<img>`（这就是"必须对照原始页面图像"的载体） |
| typed contract 录入+预检 | JSON textarea + 浏览器端结构预检（presentation 匹配、schema_version/contract_sha256 齐备、diagram nodes/edges、table cells/rows/columns、ordered_list items 且禁 continuation、constraint/formula tokens）；与服务端 `gates/review/contracts.py::precheck_contract_payload()` 一一对应 |
| 四态决策表单 | `manual_review / blocked / not_applicable / reviewed_candidate` + reviewer + 审核依据 + 五确认勾选（sourceText/anchor/sourcePage/imageHash/contractCheck） |
| 决策暂存与导出 | 决定存页面内存 Map；导出 `review-browser-decisions.json`（`examcard_review_raw_draft_manifest_v1` 信封） |

**两界原则（安全设计，选型时必须保留）**：导出的每条决定 `decision_sha256` 恒为占位串 `browser-export-pending-cli-hash`、`browser_demo` 恒 `true`、`production_fixture_authorized` 恒 `false`——在类型层面就不可能通过权威模型（`decisions.py::HumanDecision` 要求 `browser_demo: Literal[False]` + 64 位十六进制自证哈希）。回链路径只能是：`RawReviewDraftManifest` → `classify_browser_decision()`（**浏览器 reviewed_candidate 一律降格 manual_review**，r82 定式）→ `normalize_raw_draft()` 重绑定冻结候选 → 期注入的 decision_builder 于 CLI 侧重建权威 `HumanDecision`（重算哈希）。另有 `build_progress()` 进度快照模型（r87）支持可续传，但**尚无任何落盘接线**。

## 4. 本地启动指引（已验证，2026-08-12 实测）

实测输出：`queue_sha256=0b99e819d59c2ae2632c047edaf006a5a60aac19bfa7b1b0c5323041f2173eeb`、3 条目（formula/table/diagram）、HTML 12,474 字节、`image_uri[0]=/output_images/%E6%B5%8B%E8%AF%95/page_0001.png`。

**注意事项**：
- 图像可见性完全取决于**服务根**：`image_uri` 是根绝对路径，生产上服务根必须是"能按 `image_path` 找到源页图的运行根"（旧仓语料即 yijian2 仓根 `output_images/...`；T4 的 `exams/<exam_id>/` 目录契约须为此定死服务根）。

## 7. 建议：T4 v1 选型

**结论：混合式——文件侧车为契约，webui 为检查点①的可选检视器；检查点②纯文件侧车。**

1. **检查点①（step2 准入评审）：复用 webui，但只当"检视/录入器"**。理由：
   - 启动成本已实测为零新增依赖（渲染纯函数 + `http.server`，§4 两条命令）；
   - 无论用不用 UI，G-A1 队列装配与 G-A2 摄取 CLI **横竖都要做**（它们是门禁本体）；UI 只是在两者之间加一个"人看图、录契约、导 JSON"的壳，复用比重写 markdown 清单更省且已有 5 条测试兜底；
   - 权威判定天然留在 CLI（两界原则现成），驱动流程为：`run → 队列 JSON + workbench.html（打印启动命令）→ 人工导出 decisions JSON → 驱动严格摄取 → 放行 step3`。断点续跑用 `build_progress` 落盘（补 G-A3 接线）。
2. **检查点②（图像评审）：v1 文件侧车，不给 webui 加图像页**。理由：现状零界面（G-B1），补 UI 属新开发而非复用；权威路径（dispositions 映射 → `build_image_manifest` → `admit_images`）本就是文件/CLI 形态；v1 侧车 = 驱动产出 `image_review_sheet.json`（逐图 path/sha256/呈现/绑定摘要）+ 图片目录，人工回填 disposition 后驱动摄取。webui 图像评审页（顺手可复用侧栏/过滤骨架）列为 v2 增强。
3. **给 T4a 设计稿的三条硬输入**：
   - 服务根 = `exams/<exam_id>/` 运行根（保证 `image_path` 可解析），启动命令由驱动打印；
   - 通用 N 图评审清单需**新 schema_version**（G-B2，禁改 phase2r11101 三决策钉扎形态）；
   - step2 摄取 CLI 的 `decision_builder` 注入与 `classify_browser_decision` 降格语义照搬 r84 定式，不新造语义。
4. **工作量估计**：①的胶水（队列装配+启动器+摄取 CLI+progress 落盘）≈ 0.5-1 天；②的侧车三件套 ≈ 0.5 天；均在 T4 1-2 天总盘子内。若改为"给 webui 补图像评审页"则 +1-2 天且引入新前端面，不建议进 v1。
