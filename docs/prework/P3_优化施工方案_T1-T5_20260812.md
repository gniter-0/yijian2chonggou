## 1. T1 中继能力预检工具（小，~1h，零冻结面风险）

**痛点**：昨天换中继/换模型排障花了数小时（体积 502、strict 不强制、CF 首字节窗口、图像信封变体是四类独立故障）。以后中继一变，需要 2 分钟内测清"能不能用、哪不能用"。

**交付物**：`migration/relay_preflight.py`（与既有 `probe_relay_body_limit.py` 同区，后者功能并入）。

**四组探针**（各自独立开关，默认全跑；预算熔断内置）：

| 组 | 方法 | 判定输出 |
|---|---|---|
| P1 体积阶梯 | 12/40/70/120/180/260KB 填充 payload + strict 小 schema echo | 请求体上限区间 + 各级时延 |
| P2 strict 遵从 | 要求 `minItems=3` 且元素为指定 const 的数组回显；空数组/缺项=逃逸 | strict json_schema 是"强制解码"还是"仅提示"（step3 可行性的决定项） |
| P3 首字节窗口 | 诱导长思考的小输出请求（非流式 vs 流式各一次，`--deep` 才跑） | 网关掐断条件（总时长 or 首字节）与窗口估值 |
| P4 图像端点 | `GET /v1/models` 查图像模型；`--with-image` 才真出 1 张最小图 | 图像通道可用性 + 信封形态（b64/url 变体） |

**输出**：`relay_preflight_report.json` + 控制台能力矩阵，并与**需求画像**对照直接给结论：`step2a 需 ≥300KB`、`step3(v2 单卡) 需 strict 强制 + (首字节窗口 ≥150s 或流式可续)`、`step4 需图像端点`。

**费用**：默认口径 ≤12 次小调用 ≈$0.1；`--deep --with-image` 全开 ≈$0.3-0.5。
**验收**：对现有两中继复跑，矩阵与昨日实测一致（chatgpt2api-new：40-70KB 上限/strict 不强制/图像可用；2chat：体积无限/首字节 ~125s/图像未测）。
**测试**：探针构造与判定逻辑的离线单测（T4 禁网规范内，伪 transport）。

## 2. T2 生产配方产品化（中，2-4h，进引擎但不动冻结面）

**痛点**：实测达标配方（补强指令 + SSE 流式 + 失败章重发）只存在于 `migration/run_pilot_gonglu5_step2.py` 的私有子类里；未来任何考试的 live 跑都要复制补丁。

**改动清单（全部新增/可选参数，v1 行为不变）**：

1. `src/examcard/knowledge/llm.py`（Step2 执行器）
   - `OpenAICompatibleStep2Transport` 增可选构造参 `stream: bool = False`：`_raw_create` 在 stream=True 时走 SSE 聚合（拼 delta → 等价 `TransportCompletion`，保留 provider id/status/finish_reason 审计字段）。默认 False，既有行为逐字节不变。
   - 增可选构造参 `system_suffix: str | None = None`：消息构造时追加到 system 尾部（V25 模板本体零改动）。
   - **身份纪律不变**：请求 identity 的推导输入不含这两个参数（与 pilot 实测口径一致——补强在传输层注入，identity 不变）；但两者写入运行 journal（`streaming_transport` / `reinforcement_id`）保证可审计。
2. 新增 `src/examcard/knowledge/reinforcement.py`：`STEP2A_REINFORCEMENT_V1`（五条硬性要求常量：考情元数据禁产/禁拆行/忽略水印散字/diagram 必产/宁缺毋滥）+ `reinforcement_id`（内容哈希短址）。文本从 pilot 驱动原样搬运，一字不改。
3. 新增 `src/examcard/pipeline/live_run.py`（live 编排辅助库，T4 的地基）：本轨先落两件——
   - `ResendPlan`：失败样本重发的身份管理（新 `manual_reissue_reason` 后缀生成、禁复用失败身份、轮数上限），把 pilot 驱动里的重发逻辑抽为可复用函数；
   - `load_run_env()`：运行配置读取，**默认读新仓 `exam-card-engine/.env`**（gitignore 已覆盖），支持 `--env-file` 显式指定；把现 yijian2/.env 的键复制一份过来（TEXT/IMAGE 双通道显式键齐全），**从此原仓零接触**。
4. `migration/run_pilot_gonglu5_step2.py` 改薄：删私有 `StreamingReinforcedTransport` 等子类，改调引擎参数；`--reinforce/--stream/--only-samples` 语义不变。
5. 测试（tests/，全离线）：SSE 聚合单测（伪 chunk 流）、system_suffix 消息构造快照、ResendPlan 身份唯一性、env 双通道回落顺序。

**验收**：`uv run pytest` 全绿不回退；pilot step2 驱动 dry-run 全通；（报批后）任选一章 live 冒烟 ≈$0.15 复证配方等效。

## 4. T3 step3 v2 单卡回显契约（中大，4-8h，新增版本号、不触 v1）

**痛点**：v1 响应契约钉死"三代表卡一次性整体回显"（~4-6K tokens 超长受约束生成），在两中继三路径全部证伪（chatgpt2api 空数组逃逸；2chat 网关掐断/上游 APIError）。这是"新卡自动出布局→出图"的唯一硬断点。

**设计要点**：

1. 新增 `src/examcard/compilers/step3_response_v2.py`（**独立新模块**，v1 文件零改动）：
   - `SingleCardModelInput`（`schema_version: "step3-response/2.0"`）：单卡投影（contract_id/source_candidate_id/fact_ids/presentation/source_binding/visible_elements/layout），字段口径与 v1 的卡对象一致，仅把"三卡数组"降为"单卡"；
   - `build_single_card_model_input(contract, projection)`：从 `Step3Compilation` 的逐卡（contracts[i] + model_input.cards[i] 保序对应，pilot 已验证）构造；
   - `RESULT_SCHEMA_V2`：strict json_schema，`draft_cards` `minItems=1, maxItems=1`，逐字段 required + `additionalProperties:false`（回显确认语义与 v1 相同：一字不改逐字段回显）；
   - `make_single_card_inspector(model_input)`：内容门禁（逐字段等值 + schema_version 检查 + 空逃逸判负）。
2. 发送侧复用 providers 信封检查 + T2 的流式 transport；每卡输出 ~1-1.5K tokens（v1 的 1/3），2chat 5.6-sol 大概率可过（step2b 同量级 5/5 全绿是先例）。
3. 批量执行器进 `pipeline/live_run.py`：逐卡循环 + `ResendPlan` + 预算熔断（cards×2）。
4. 测试（离线）：schema 快照、inspector 正/负样本（合规回显/字段漂移/空数组逃逸/schema_version 错版）、构造函数对拍 v1 投影。
5. **live 实测（报批后，≈$0.3-0.5）**：黄金五章 16 卡在 2chat+5.6-sol+流式下跑单卡回显；**验收 ≥14/16 首发或单次重发通过**（对齐 step4 首发成功率口径）。
6. 冻结纪律：v1 的 `step3_response.py`、法定哈希、既有 fixture 全部零改动；v2 仅新增文件与测试。
