## 2. 实战修正两处（彩排拓出，随本报告入库）

1. **release 构建器内容级门禁**（`compilers/step4_echo_bridge.py`）：B1 真 typed fixture 的离线复合 `gate.valid=False`，构建器改为校**内容级六项**（source_fixture_authorized / source_contracts_valid / provenance_valid / source_text_exactly_once / model_input_clean / deterministic_draft_valid）全真，复合 valid 刻意不要求。**根因记录更正（独立复核 §2a，`P3_P8独立验证_桥实现与彩排双推送复核_20260813.md`）**：复合失败的实际项是 `fail-closed-regressions`——r9 回归矩阵的 `missing-list-item` 探针在无 ordered_list 卡的批上「unexpectedly accepted」（探针适用性假阳），而非本报初判的 `batch_generation_authorized`（该常量为 False 时 downstream-disabled 检查恰通过）。内容级六项替代在工程上仍然成立（内容面完整保留、授权语义确由签发 handoff 接替）；复核人建议的可选小卡：r9 回归矩阵改呈现族感知（批内缺族探针跳过），复合 valid 即可对 echo 批恢复可用。
2. **词级门禁 live 转写改 Responses API 路**（`migration/run_step4_text_gate.py`）：chat/completions+image（非流式与 SSE 流式各实测一次）均被 2chat 120s 源站窗口掐断（http=524，Cloudflare origin_response_timeout 取证）；A2 校准实录的 `provider_id=resp_…` 谱系证实视觉输入走 `/responses` 3-18s/卡返回。转写面改 `client.responses.create(input_text+input_image)`，transcriber_id 携 `+responses` 谱系；另补 `--release-family pilot|echo` 真值家族开关（echo 家族=release visible_texts）。
