# 知识结构化（PDF → 可溯源知识点）

## 一句话说明

把一份 PDF 拆成一条条**知识点**，每条知识点里的每一句话、每一个数字，都能在 PDF 原文里逐字找到出处。

```
PDF ──第一步 提取──▶ 每页文本 + 截图 ──第二步 结构化──▶ 知识点 JSON + 核对报告
```

本 Skill 只做到"知识点 JSON + 核对报告"为止。后面的"写绘图提示词"（原第三步）和"出图"（原第四步）**不在范围内**。

---

## 五条铁律（任何一条被违反，结果作废）

1. **原文文本是唯一真相。** PDF 里程序提取出的文字说了算；页面截图只用来看懂版式（表格怎么分行分列、流程图箭头指向哪里），**不许从截图里重新认字**。
2. **只摘不写。** 不概括、不改写、不润色，也不用"等"字省略。知识点里的文字必须是原文的连续片段（允许去掉换行和空格）。
3. **一个不漏。** 原文里的序号条目（①②③、(1)(2)(3)、1）2）3）、A/B/C……）以及所有数字、单位、比较符（≥ ≤ > < ~ ±），全部保留，个数必须和原文一致。
4. **原文有错也照抄，但要标出来。** 发现教材错字（例如把"上路堤"印成了"上路提"），content 里保持原样，另在 `quality_flags` 里写明 `source_typo: 上路提→上路堤?`。是否更正交给人来决定。
5. **说不清出处的，不算知识点。** 每个知识点都必须带 `source_pages`（以及可选的 `evidence_refs`），并且要通过第 2.6 节的溯源核对。没通过的不能交付，只能放进"待人工确认"清单。

---

## 第一步：PDF 提取（纯程序，不调用大模型）

**目的：** 把 PDF 变成"每页一份准确文本 + 一张截图"，作为后面所有工作的地面真相。

**直接运行：** `python scripts/extract_pdf.py <文件.pdf> <输出目录> [--dpi 150] [--noise 额外噪声正则.txt]`

做法：

1. 用 PyMuPDF（`fitz`）逐页处理：
   - `page.get_text("text")` 取文本；需要定位时用 `get_text("dict")` 保留每行的坐标。
   - `page.get_pixmap(dpi=150~200)` 存截图 `page_0001.png`。
2. **清理噪声**（用正则，宁可少删也不错删）：
   - 广告、水印、联系方式，例如"联系电话：""押题联系""名师面授""视频12-15集"；
   - 每页重复出现的章节页眉、页脚、页码；
   - 连续 3 个以上的空行压缩成 1 个。
3. **扫描版 PDF：** 页面取不出文本时，才对截图做 OCR，并把该页标记为 `text_source: "ocr"`，信任度降一级，后面要重点人工抽查。
4. 输出 `extraction.json`：

```json
{
  "source_file": "01 路基施工准备.pdf",
  "chapter": "路基施工准备",
  "total_pages": 12,
  "pages": [
    {"page_num": 1, "text": "……清理后的原文……", "text_source": "pdf", "image_path": "page_0001.png"}
  ]
}
```

**第一步自检：**
- 页数是否和 PDF 一致；
- 抽 3 页，把文本和截图对照看：有没有整段缺失，有没有乱码。

## 第二步：知识结构化（大模型 + 程序把关）

整体顺序：**切证据 → 分批提取 → 去重总审 → 逐点补漏 → 机械纠错 → 溯源核对 → 事实规则校验 → 覆盖检查**。

每个阶段完成后都要把进度存盘（例如 `xxx.progress.json`），中断后可以接着跑。

### 2.1 切证据（推荐，来自新引擎）

把每页文本按行或按句切成一小段一小段的"证据"，每段给一个稳定编号：

```json
{"evidence_id": "ev:<sha1前24位>", "page": 3, "line": 17, "text": "长度宜不小于200m。"}
```

编号用 `sha1(文件名 + 页码 + 行号 + 文本)`，这样同样的输入永远得到同样的编号。有了证据编号，后面每个知识点都能精确指回"第几页第几行"。

### 2.2 分批提取

- **分批：** 每批 5 页，相邻两批重叠 2 页（第 1–5 页、第 4–8 页……）。重叠是为了防止跨页的知识点被切成两半。
- **每页按顺序喂给模型：** 先给"[第 N 页 · PDF 提取文本（准确）]"，再给截图。
- **参数：** `temperature=0`，要求严格输出 JSON。
- **提示词：** 用 `references/prompts.md` 里的《提取提示词》，把 `{领域}` 换成实际学科。
- **拆分原则：**
  - 一个完整的方法、工艺、试验、标准、分类算一个知识点，不在步骤中间拆开；
  - 超过约 8 个要点才考虑拆成多个；
  - 一页末尾的①②③和下一页开头的④⑤属于同一个知识点。
- **程序立即校验**（不合格就重试，最多 3 次）：
  - 输出是合法 JSON，并且有 `knowledge_points` 列表；
  - `source_pages` 落在本批页码范围内，并且不是"把本批所有页都填上"这种偷懒写法；
  - `content` 不为空，不是只有标题。

### 2.3 去重总审（只删不改）

重叠分批一定会产生重复。处理顺序：

1. **先用程序删掉完全相同的**：标题和内容都一样，就合并 `source_pages`。
2. **再让模型审一遍**（《去重提示词》），规则是：
   - 只有内容重合超过 80%（同一对象、同一数值、同一适用范围）才删；
   - 删的时候保留更完整的版本；
   - 含有独特数值或标准的知识点，一律不删；
   - 不同的试验或工序（例如水压试验和气压试验）不算重复；
   - **拿不准就保留**——多留一条可以接受，误删不可以；
   - **模型绝对不许改 content 的任何一个字。**
3. **最后按标题做一次全局去重**：只给模型看"标题 + 页码 + 内容前 80 字"，由它指出疑似重复的配对，再由程序合并。

### 2.4 逐点补漏（只追加不改）

对每个知识点，把它的出处原文和当前 content 一起交给模型（《补漏提示词》），检查三件事：
- 本知识点范围内的序号条目是否齐全；
- 数值是否齐全；
- 有没有整段被跳过。

有遗漏时，**只允许在 content 末尾追加**，并且追加的内容必须来自原文、属于本知识点的范围（不能把同一页上别的标题下的内容拉进来）。

程序同时做一次"数字对账"：原文里有、content 里没有的数字，列出来供参考。

### 2.5 机械纠错（纯程序，以原文为准）

1. **形近字纠正：** 把 content 和原文逐段对齐。content 里出现原文中没有、但和原文只差一个形近字的词（储/笸、垫/吊、灌/冲、氯/锰、焊/悍、碳/炭……），一律改回原文的写法。每个学科维护一份形近字表。
2. **截断补全：** 页面边界处常出现半个词，例如"耐高≥1100℃"应为"耐高温≥1100℃"，"证明文"应为"证明文件"。用原文补到最近的标点为止。**补全结果必须通过 7 道安全过滤，任何一道不过就放弃这次补全**：
   1. 补后比补前长出超过 15 个字（说明补过头了）；
   2. 删掉太多字；
   3. 补前和补后的相似度（最长公共子序列比例）过低；
   4. 混进了题目选项、"练习"字样等格式异常的内容；
   5. 汉字被替换成了标点；
   6. 出现了回声式重复；
   7. 混进了 PPT 页眉或章节噪声，或者把原文口诀拆坏了。

### 2.6 溯源核对（硬门槛，来自新引擎）

用 `scripts/check_grounding.py` 做，必须**全部通过**才能交付。

| 检查项 | 规则 |
|---|---|
| 片段溯源 | content 按换行、句号、分号切成片段，每个片段做 NFKC 规范化并去掉空白后，必须是它 `source_pages` 对应原文的子串 |
| 数字溯源 | content 里出现的每个数字，都必须出现在它所引页面的原文里（避免凭空多出一个数字） |
| 序号计数 | content 里的序号条目个数，要等于 `point_count` |
| 页码合法 | `source_pages` 不为空，并且都在 PDF 页码范围内 |
| 完全重复 | 不允许出现两条内容完全一样的知识点 |
| 行覆盖（查漏） | 原文每一行（去空白后不少于 2 个字）都要出现在引用该页的某个知识点里；没出现的列为"可能遗漏"，逐条确认是噪声还是漏了。加 `--strict-coverage` 时算失败 |

没通过的知识点，**不许让模型"自圆其说"地改写**，只有两种处理：
- 改回原文片段；
- 移进 `needs_review.json`，交给人来判断。

### 2.7 事实规则校验（按学科配置，可选但推荐）

每个学科一个 YAML 配置文件，工具本身和学科无关。支持 6 种规则：

| 规则 | 检测什么 | 例子 |
|---|---|---|
| `range` | 数值超出合理范围 | 湿度 > 120% |
| `mutex` | 同一段里出现互斥的词 | "含卤"和"不含卤"同段 |
| `typo` | 已知形似字、错字 | "棚纤维"（应为"硼纤维"） |
| `known_error` | 教材原文已知的错误（只提示） | "上路提" |
| `consistency` | 知识点之间或知识点内部的数值应一致或应不同 | A 类和 B 类的指标不应相同 |
| `forbidden` | 兜底禁用的字符串 | 任意想拦截的字串 |

### 2.8 覆盖检查与碎片过滤

- **页面覆盖：** 有正文、却没有被任何知识点引用的页，要列出来。这类页可能是练习题页，也可能是知识点被误删了。
- **碎片过滤：** 下面几类内容**不单独成为知识点**，而是打上 `kp_type` 标签另存：
  - 只有表头的残片（如"地段 代表"）；
  - 缺题干或缺答案的例题选项；
  - 孤立的分值数字。
- **最后：** 按出处页码排序，重新编号为 `001`、`002`……

## 输出格式：`structured.json`

```json
{
  "source_file": "01 路基施工准备.pdf",
  "chapter": "路基施工准备",
  "total_points": 16,
  "dropped_lines": [
    {"page": 1, "text": "P1~ 52    第1 章 路基工程", "reason": "教材页码标注；章名已写入 001"}
  ],
  "knowledge_points": [
    {
      "id": "014",
      "kp_type": "knowledge",
      "title": "路堤填料最小承载比和最大粒径要求",
      "content": "原文逐字片段，保留序号、数值和比较符",
      "table": {
        "header_groups": [{"text": "填料最小承载比CBR（%）", "span": [3, 5]}],
        "headers": ["填料应用部位（路面底面以下深度）（m）", "", "", "高速、一级公路", "二级公路", "三、四级公路", "填料最大粒径（mm）"],
        "rows": [["上路床", "", "0~0.3", "8", "6", "5", "100"],
                 ["下路床", "轻、中及重交通", "0.3~0.8", "5", "4", "3", "100"],
                 ["下路床", "特重、极重交通", "0.3~1.2", "5", "4", "3", "100"]]
      },
      "point_count": 0,
      "key_words": ["CBR", "最大粒径"],
      "annotations": ["需要红色强调的原文片段（必须是 content 的子串）"],
      "diagram_type": "table",
      "diagram_elements": ["只写原文里有的元素名"],
      "source_pages": [3],
      "evidence_refs": ["ev:…"],
      "quality_flags": ["source_typo: 上路提→上路堤?"],
      "grounding_status": "pass"
    }
  ]
}
```

字段说明：
- `dropped_lines`：**有意不收录的原文行必须在这里登记原因**（教材页码、残留噪声、纯图片说明等）。没登记的原文行一律按"可能遗漏"报出来。
- `kp_type`：取 `knowledge`（知识点）、`overview`（章节结构、思维导图）、`score_table`（历年分值）、`exam_question`（真题或例题，必须题干、选项、答案齐全才保留）、`fragment`（碎片，不交付）之一。
- `table`：原文是表格时**必须填写**。表头和单元格的文字也必须是原文（不能自己起列名，例如原文没有"交通等级"四个字就不能写），没有表头的列留空字符串。多级表头用 `header_groups` 表示上层表头，`span` 是它覆盖的列号范围（从 0 开始）。合并单元格要展开到每一行，例如"下路床"的两种交通等级各写一行，CBR 值在两行里重复填写。不能只交一串换行拼起来的文字，否则下游会读错行列。
- `annotations` 和 `diagram_elements`：只能引用原文，不能自己发挥。下游画图时，只允许用这些字。

## 交付前验收清单

- [ ] `check_grounding.py` 退出码为 0：未溯源片段 0 个，未溯源数字 0 个。
- [ ] 每张表格都有 `table` 字段，行数和列数与原文一致，并抽查 3 个单元格。
- [ ] 序号条目计数全部一致。
- [ ] 未覆盖的页都已经解释过（是练习题页、目录页还是空白页）。
- [ ] `quality_flags` 里的教材错字已经列给用户。
- [ ] `needs_review.json` 为空，或者已经交给用户确认。
- [ ] 人工随机抽查 5 条知识点，和 PDF 原页对照阅读，确认没有张冠李戴。

## 踩过的坑（真实案例）

| 现象 | 原因 | 对策 |
|---|---|---|
| 图上出现 CBR "200/300"、"≥2" 等错数 | 旧版第二步之后没有逐字溯源，下游又自己发挥 | 2.6 节的数字溯源设为硬门槛 |
| "耐高≥1100℃"之类的半截词 | 页面边界截断 | 2.2 节分批重叠 + 2.5 节截断补全 |
| "储罐"被写成"笸箩" | 模型从截图里重新认字 | 铁律 1 + 2.5 节形近字纠正 |
| 表格变成一长串换行文字，行列错位 | 只存了 content 文本 | 必须填写 `table` 结构 |
| 去重时把"水压试验"和"气压试验"合并了 | 去重标准太松 | 80% 门槛、独特数值不删、拿不准就保留 |
| 补漏时把隔壁标题的内容补了进来 | 证据范围太宽 | 补漏只限本知识点范围，并且只追加 |
| 出现"地段 代表"这种单独成卡的碎片 | 表头被当成知识点 | 2.8 节碎片过滤，跨页表格要合并 |
| 整章挤成 1 个知识点，后面一张图塞满一章 | 拆分粒度失控 | 遵守拆分原则：一个方法、试验或分类算一条 |
| 补充题的答案（"沉降差"）被并进正文参数 | 把例题和正文混在一起 | 例题单独作为 `exam_question`，题干、选项、答案齐全 |
| 表注 2、表注 3、原文口诀、例题答案被漏掉 | 只查"有没有出处"，不查"有没有漏" | 2.6 节行覆盖检查 + `dropped_lines` 登记 |
| 表格里 8 改成 9 没被发现 | 单个数字按子串比对，借了原文"1.9"里的 9 | 纯数字格按完整数字比对 |

## 文件

- `references/prompts.md`：提取、去重、补漏、截断修复四个提示词模板，学科通用。
- `scripts/extract_pdf.py`：第一步 PDF 提取，依赖 PyMuPDF。
- `scripts/check_grounding.py`：2.6 节溯源核对的参考实现，只依赖 Python 标准库。用法：

```bash
python scripts/check_grounding.py extraction.json structured.json --report grounding_report.md
```
